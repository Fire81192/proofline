## 插件与工作区是两样东西

这个仓库（`proofline/`）**只有代码**：`src/`、`test/`、`tools/`、文档。里面没有一条知识、没有一张图、没有任何数据。

用到的东西全在 `workspace/` 下，按项目分开放：

```
专业代理层/
  proofline/                 插件本体 —— 可以整个复制走、单独发布
    src/ test/ tools/
  workspace/
    ppg2abp/                 工作区：一个项目
      entries/               条目库（含 raw/ 快照与 .log/）
      knowledge-map.json     这个项目需要什么知识
      progress.json          我个人到哪了
      复现/                  分析脚本与报告
      证据册.html 课程地图.html   生成物，随时可重建
    self/                    另一个工作区：关于插件自己设计的条目
```

**为什么要分**：数据会越长越大、含第三方原文快照、还含个人进度；代码要干净、能发布、能给别人用。混在一起，两边都不可维护——删一条数据要动插件仓库，升级插件又怕碰到数据。

### 用法上的变化

命令的第一个位置参数就是工作区里的条目目录，默认是 `entries`。所以：

```bash
cd workspace/ppg2abp
proofline check          # 读 ./entries
proofline map            # 读 ./knowledge-map.json，写到 ./
proofline view           # 写到 ./证据册.html
```

在插件目录里直接跑会报「条目目录不存在：entries」——**这是故意的**，它不该有默认数据。

## 怎么启动（三种，从省事到精确）

**一、双击 `专业代理层/启动.cmd`**

会自己起服务、自己开浏览器。关掉那个黑窗口就停。它用的是 `%~dp0`，所以整个文件夹搬走也还能用。

**二、库目录里敲一条命令**

```bash
proofline open          # 起服务 + 开浏览器
```

命令是全局安装过的（`npm link` 一次即可）。端口被占会自动往后挪，不用手动数。

**三、npm 脚本**

```bash
npm start               # = proofline open
npm run check           # 校验全库
npm run map             # 重生成课程地图.html
npm run view            # 重生成证据册.html
npm run audit           # 隐私自查
npm test                # 全部测试
```

### 命令速查

| 想干什么 | 敲什么 |
|---|---|
| 看现在的库 | `proofline open` |
| 库有没有坏条目 | `proofline check` |
| 这条还能不能用 | `proofline status <id>` |
| 记一次实测（脚本 + 输出 + 期望值） | `proofline run <id> --script ... --output ... --expect 键=值` |
| 想给一条结论加自动检查，但想不出查什么 | `proofline draft <id>` |
| 动手之前先问一句 | `proofline guard --target <路径> [--action delete]` |
| 重新出课程地图 | `proofline map`（有硬问题就不出图，退出码 1） |
| 让 AI 帮你画地图 | `proofline map --brief`（输出任务书，整段粘过去） |
| 重新出证据册（静态，可发人） | `proofline view` |
| 查隐私泄露 | `proofline audit` |
| 几个库各自什么样 | `proofline projects workspace` |
| 文档里要写数字（别手抄） | `proofline stats workspace` |
| 这条有没有被手改过 | `proofline trace <entries 目录>` |
| 整体体检（隔离 / 留痕 / 地图） | `proofline doctor <entries 目录>` |
| 证据册要发给导师批注 | `proofline view <entries 目录> --md`（输出 .md，能进 diff） |
| 查有没有「写进去没人读」的字段 | `proofline fields --audit workspace` |
| 让新建必须走草稿 | `proofline inbox on <entries 目录>` |
| 把草稿搬进正式区 | `proofline ingest <_inbox 目录> --into <entries 目录>` |
| 全看一遍 | `proofline --help` |

退出码：`0` 通过 / `1` 有 hard_fail 或 dirty / `2` 用法错 / `3` 内部错误。

`guard` 是唯一一个退出码只答「能不能直接继续」的命令：`0` 能，`1` 不能（ask 和 deny 都要人看一眼，区别在 JSON 的 `decision` 字段）。

## 它和别的笔记库差在哪

**一、证据是算出来的，不是写上去的。**

你说「某视频说 XML 标签更稳」，系统要你把原文（或转录）存下来，再挑一句引文。之后每次读，它都会重新在原文里搜这句。搜不到、或者原文被改过一个字，这条的「来源维度」立刻降级。

存下来的字符串不能证明任何事，能重新定位的区间才能。

**二、判定拆成两个维度，互不污染。**

| 维度 | 问的问题 | 谁判 |
|---|---|---|
| `evidence_status` | 这个来源**确实这么说了**吗 | 代码（引文在不在原文里） |
| `world_status` | 这个主张**在世界里是真的**吗 | 人 / 查证 |

这两件事经常指向相反方向：来源明确说了 X，而 X 是假的。

拆开之后，「大多数碎片找不到权威源」不再是死局——不是整条不可用，是**分开报**：来源层面可引用，事实层面标未定。

**三、状态不存，读时算。**

磁盘上写着 `evidence_status: supported` 不算数。每次读都重核一遍快照哈希和引文位置，核不过就降级。

存下来的状态会撒谎——原文早改了，字段还写着「已核实」。而撒谎的状态比没有状态更危险，因为下游会信它。

**四、快照是二手的时候，必须说清原件在哪。**

快照很少是「原文本身」。论文的原文是 PDF，手上是解析出来的文字；视频的原文是画面和声音，手上是转录。中间隔着一道有损转换。

所以有个字段 `source_extraction`（原文 / OCR / PDF抽取 / 转录 / 摘要 / 表格压平），只要不是「原文」，就必须填 `source_original` 说明原件在哪。

**最后一档「表格压平」是单列出来的，因为它说的不是手段，是损失。** 内容一个字不少，但行列关系没了，一整张表变成 `Ⅰ阶段目标值701503575` 这样一串。校验过得去（逐字确实对得上），人读不懂。不单列出来，下一个读这条的人会以为自己眼花。

不记这一项，就等于假装手上的文本和原件等价。而 OCR 会认错字——引文能定位到「我们手上的文本」，不代表能定位到原件。

## 不会有的开关

有三样东西永远不做开关——不是没来得及，是关掉就等于把这个工具删掉：

- **留痕**（`entries/.trace.jsonl`）。关了之后，所有条目和「从没被校验过」没有区别。
- **未受控不给引用**。这是最后一道。关掉之后，前面所有检查都退化成提示。
- **`source_sha256` 校验**。关掉之后，引文和原文的对应关系只剩一句口头承诺。

严格程度可以调（`--strict`、`--quiet`、`--out`、`--adopt`），并且降级之后输出里一定看得见。
但「要不要」没有。

这条是用户 2026-11-22 明确定的边界：**这三样以后不在讨论范围。**

## knowledge-map.json 的格式

地图是一份独立的 JSON，和条目库解耦：删掉它，条目一条不受影响。

```jsonc
{
  "schema": 1,
  "project": "空气质量标准",
  "blocks": [
    {
      "id": "read-source",            // 能力块 id，唯一
      "name": "取准原文",              // 显示名
      "basis": "条目",                // 这一块主要靠什么撑：条目 / 实测 / 判断
      "needs": ["legal-reading", "pdf-tooling"],   // 需要哪些能力
      "needLevels": {                 // 各能力需要几级（不写就没法判断够不够）
        "legal-reading": 2,
        "pdf-tooling": 2
      },
      "entries": ["2026-11-22-cn-3095-35"],   // 挂在这块上的条目 id
      "gap": "同一件事的原文长得不一样，取数方式也不同。"   // 这一块还缺什么
    }
  ],
  "domains": [
    {
      "id": "legal-reading",
      "name": "法律文本阅读",
      "levels": ["能读条款", "能分辨效力等级", "能判断适用时间"]
    }
  ]
}
```

三个约束，违反就是硬错（`map` 退 1，不出图）：

1. `blocks[].entries` 里的 id 必须真存在——悬空引用等于「这块有支撑」是假的
2. `needLevels` 的键必须是 `domains` 里有的 id
3. `levels` 不能为空——没分级的学科没法判断「够不够」

## 它和你的其他工具什么关系

**采集不是它的事。**

| 工具 | 干到哪一步 | 产出 |
|---|---|---|
| Agentero | PDF → 干净文本 + 中文讲义 | `PAPER.md`、`NOTES.md` |
| 视频转录类工具 | 音视频 → 转录稿 | 一段文本 |
| **proofline** | **文本 → 可核条目** | `entry.md` + 快照 |

Agentero 的引用长这样：`[Section 2.3](papers/<id>/<id>.pdf#section=2.3)`。那是**指路**——告诉你这段在第 2.3 节，你自己去读。它没有字符级定位，没有哈希，也没有读完重核。

它产出的是给人看的讲义。讲义不能被机器判真假，而 proofline 存的正是能被机器判的东西。

所以两者是上下游，不是替代。已经在做的事不重做，只把产出接住：

```bash
proofline import 2026-11-21-transformer-no-recurrence \
  --paper "%AGENTERO_VAULT%/papers/1706.03762" \
  --claim "Transformer 不用循环结构，只靠注意力链建立全局依赖" \
  --quote "In this work we propose the Transformer, ..." \
  --kind 方法 --layer 标准
```

`import` 会自动做四件事：

> 不传 `--evidence` 时按 `unresolved` 入库，并提示。它不会替你说「来源确实这么说了」——
> 判定只能由人写，`new` 是这样，`import` 也一样。

1. 读 `metadata.json` 的 `body_source`，映射成 `source_extraction`（ocr → OCR，latex → 原文）
2. 取正文：有 `PAPER.md` 用它；LaTeX 论文没有，就按文件名排序拼 `source/*.tex`
3. `body_quality: low` 时自动加一条**不阻塞**的缺口：引用前对照 PDF 核一遍
4. 算快照哈希、跑同一套校验

**claim 和引文仍然要你给**，因为「哪句是要点」是判断，不是解析。

## 可选：把引文钉到原件的页码和框上

核心只保证「这句话在这份文本里」。如果原件是 PDF，还能再进一步：
**第几页、页面哪个框**。人一眼能核，机器也能截出来。

```bash
python tools/locate.py --entry entries/<id> --pdf 原件.pdf --verify
```

它写 `raw/boxes.json`，之后 `status` 会多一行：

```
原件定位      全部命中
  p1/19  跨1行  [178.35, 284.83] → [421.94, 293.97]
```

`--verify` 会把每个框裁成 `raw/box-N.png`，肉眼核一眼就知道框对不对。

**这是可选增强，不是核心。** 没装 pdfplumber 也能用核心，只是没有页码。

### 三个坑（都是踩出来的，别重踩）

**一、不能对 `page.chars` 全局排序。** 中文期刊 PDF 里标点常被单独摆位，按坐标排序会把「、、、」挤到句首：

```
实际流：…包括公开数据集评估标准预处理方法…
标点跑到：，，PPG 、 、 、
```

带标点的引文永远匹配不上。必须先用 `extract_text_lines()` 分组。

**二、不能用 `line["text"]` 算字符位置。** pdfplumber 会按间隙插空格，中文行 46 行里 35 行长度和 chars 对不齐。文本一律由 chars 拼出。

**三、连字会让映射漂移。** PDF 里 `fi` 是一个字形但 text 是两个字。按「一字框一位」扩映射，每遇到一个 `fi` 就错开一位，整页能漂十几位——最后框到不相干的行上。这个 bug 只有把框裁出来看一眼才会发现。

## 建一条

`--spec` 是一个 JSON：

```json
{
  "claim": "一句话主张，能判真假的那种",
  "kind": "参考架构",
  "layer": "标准",
  "basis": "条目",
  "source_kind": "项目",
  "source_uri": "https://...",
  "source_published_at": "2024",
  "source_available_basis": "刊头标注 2024 年第 5 期",
  "source_extraction": "OCR",
  "source_original": "原件 PDF 的路径",
  "evidence_status": "supported",
  "world_status": "unresolved",
  "quotes": ["原文里的那一句，逐字"],
  "snapshot_from": "/某个/原文.txt",
  "gaps": [
    { "question": "还缺什么才能下结论", "action": "search", "blocking": true, "dimension": "world" }
  ],
  "added_at": "2026-11-21"
}
```

`source_published_at` 支持三种精度：`2024` / `2024-05` / `2024-05-17`。
不确定精确到哪天，就只写年——**别补全**。补出来的日期看起来是精确的，比没有日期更糟。

写进去之后长这样：

```
entries/<id>/
├── entry.md          # frontmatter + 说明
└── raw/source.txt    # 原文快照
```

`source_sha256` 由程序算，不用你填。

## 依据三档：读来的、跑出来的、想出来的

`basis` 是一个必填字段，回答「这条主张是**怎么知道的**」：

| 取值 | 意思 | 要求 |
|---|---|---|
| `条目` | 从原文读来的 | 必须有快照 + 能定位的引文 |
| `实测` | 自己跑出来的 | 必须有 `runs` |
| `判断` | 推出来的 | 不要求出处，但**永远不能当依据** |

### 为什么需要第三档

前两轮跑下来，22 条条目里 21 条停在「世界维度 unresolved」。原因不只是没人填——**纯推理的结论根本进不了库**：

要么必须找到一份出处（于是它被写成「条目」，尽管原文并没说这个结论），要么塞进 `kind: 观点`（而 `kind` 说的是「这条怎么被用」，不是「凭什么知道」）。结果是这类结论只能留在报告里，下次谁都不记得它是怎么来的。

而这类结论恰恰是最要紧的：「MAE 下降但形状没学到」不是任何文献说的，也不是脚本直接跑出来的，是把两个数字放在一起看出来的。

### 给判断档开的口子，和上的三道锁

```yaml
basis: 判断
evidence_status: not_checked     # 原文没说这个结论
quotes: []                       # 没有引文
gaps: [{"question":"把训练量提到论文量级后波形相关是否上升",
        "action":"reanalyse","locator":"train_small.py 提高 --n",
        "blocking":true,"dimension":"world"}]
```

少一道锁，这个口子就变成「随便写点什么都能入库」：

1. **不许声称来源支持它**——`evidence_status` 只能是 `not_checked`
2. **必须说明打算怎么验证**——`gaps` 不能为空
3. **不许同时挂实测**——跑过了就算实测，改 `basis` 去

### 它和 layer 不是一回事

`layer` 说的是「能不能用」（线索 / 标准），`basis` 说的是「凭什么知道」。两件事正交：

- `basis: 判断` + `layer: 标准` = 想清楚了，可以拿来讨论，**但不能当依据**
- `basis: 判断` + `layer: 线索` = 一个猜测

派生状态里，判断档的 `citable` 和 `decisive` **恒为 false**，哪怕层级是标准、哪怕世界维度有结论。这条在代码里是冗余检查——现在的规则下它自然为 false——但冗余要留着：哪天有人放宽了 evidence 的判定，这里不会跟着悄悄放行。

**用推出来的结论去否定别人，是这套工具最该拦住的一种用法。**

```bash
proofline status 2026-11-22-data-volume-not-architecture
```
```
类型 / 层级   观点 / 标准 / 依据：判断
来源形态      （判断档，无来源）
能引用        否
能下判断      否
阻塞缺口：
  [world]    把训练量提到论文量级后，波形相关与振幅保留是否显著上升
```

它能存在，能被 `review` 看见，能承载验证计划——但不能用来否定任何人。

## 第二维度怎么才算活

`world_status` 很容易变成摆设——所有条目都写 `unresolved`，等于没这一维。

第一轮复现跑完，22 条条目里有 21 条停在这里。原因不是懒：大多数结论**根本没有第二份来源**，只有「我自己跑过」。只认 corroborations 的话，这一维就永远是空的。

所以有两条路，两条都算数，但不能互相冒充：

| 路径 | 回答的问题 | 形态 |
|---|---|---|
| `corroborations` | 别人也这么说吗 | `{uri, sha256, snapshot, quote}` |
| `runs` | 我自己跑出来是这样吗 | `{script, script_sha256, output, output_sha256, expect, at}` |

### 路径一：独立佐证

> **`world_status` 写 `supported`，就必须至少给一条 `corroborations`（独立佐证）或一条有效 `runs`（实测复跑）。**

佐证不是一句话，是一个可复核的形态：自己的快照、自己的哈希、必须能定位的引文。

**路径安全分两层**，缺一层就漏：

| 层 | 做什么 | 挡什么 |
|---|---|---|
| `validate.js` | 字符串粗筛：不以 `/` `~` 开头、不含 `..` 和 `\`、不是盘符开头 | 手写的越界路径，并给出清楚的报错 |
| `store.js` | `resolveInside()`：解析成绝对路径后，验证仍在条目目录内 | 盘符路径、网络共享路径、符号链接这类绕过 |

只做字符串检查挡不住盘符；只做解析检查报错说不清是哪儿不对。**两层都要有。**

```bash
proofline corroborate <id> \
  --source 第二来源.html \
  --uri https://... \
  --quote "原文里那一句"
proofline set <id> world_status supported
```

顺序不能反。先改 `supported` 会被校验拒：

```
拒绝写入：
  world_status 写 supported，就必须至少给一条 corroborations（独立佐证）或一条 runs（实测复跑）
```

### 路径二：实测复跑

一条 `run` 不执行脚本。它做的是**冻结**——跑的是哪一版脚本、吃的是哪份上游产物、出来的是什么输出、期望值在那份输出里找不找得到。

```bash
# 第一步：训练，产出模型和训练指标
proofline run <id> \
  --script 复现/train_small.py \
  --output 复现/out/train_small.json \
  --expect final_mae_mmHg=18.92532733578351 \
  --cmd "python train_small.py --n 1200 --epochs 2"

# 第二步：评估，吃上一步的模型，产出指标
proofline run <id> \
  --script 复现/make_figures.py \
  --output 复现/out/metrics.json \
  --input 复现/out/unet_small.keras \
  --input 复现/out/train_small.json \
  --expect mae_mmHg=18.92532733578351 \
  --expect mae_const_mmHg=19.58927964737592
```

四点成环，缺一环这次实测就清零：

| 点 | 核什么 | 不成立意味着 |
|---|---|---|
| `script_sha256` | 脚本内容没变 | 脚本改了，结论没跟着重跑 |
| `inputs` | 上游产物没变 | 模型被换了 / 中间数据被重算，而指标还是旧的 |
| `output_sha256` | 输出快照没被改 | 那份输出不是当时那份 |
| `expect` vs `output` | 每个期望值要作为**完整 token**出现在输出里 | 「我记得跑出来是 4.02」和「4.02 在那次输出里」是两件事 |

`inputs` 是后加的，因为它缺了会出真事：第一次记录时只写了第一环的脚本 `train_small.py`，配了最后一环的输出 `metrics.json`——**而 metrics.json 是 `make_figures.py` 写的**。脚本和输出跨了两环，工具完全没反应，因为它只核两个哈希，不核因果。

真实实验几乎都是链式的。只记本脚本的哈希，抓不到「模型被换了一个」——而那才是最常见的失效方式。

第三条（`expect` 对不上）是整个机制的核心。**`run` 命令当场拒绝入库**（exit 1），而不是记一条核不过的记录：

```
期望值在实际输出里找不到，这次实测不成立：
  mae_mmHg = "10.5"
要么期望写错了，要么结论要改。两种情况都不该入库。
```

### 它保证不了什么

说清楚三件它做不到的，免得当成比实际更强的保证：

**一、它不验证「这个脚本能产出这个输出」。** 两边都是人填的，工具只核哈希对得上、期望值在输出里找得到。脚本和输出错配，它查不出来——上面那个 `train_small.py` + `metrics.json` 的例子就是我自己踩的。

**二、它保证的是「这一次的记录没被改过」，不是「结果可重复」。** 实测过：同机同参数重跑训练，五个关键值逐位一致，`metrics.json` 连字节都没变。但 TensorFlow 自己每次启动都在警告「oneDNN 会让浮点结果略有不同」；换机器、换版本、换线程数，那一层它不管。

**三、workspace 之外的输入它看不见。** `train_small.py` 里写死了 `ZIP = '<U盘>/codes/abps (2).zip'`，数据在 U 盘上。`inputs` 只收 workspace 内的相对路径，所以这个真正的输入源不在记录里——U 盘拔了、换台机器，这条就复跑不了，而工具不知道。

### 为什么工具不替你跑

重跑要环境、要数据、可能有副作用。一旦它自己跑起来，「可复现」就变成「工具说它可复现」。

它保证的是另一件事：**你跑过的那一次，后来没有被悄悄换掉。**

### 它会自己掉下来

佐证快照被改一个字、引文定位不到、脚本动一行、上游模型换了一个——`status` 立刻降级：

```
世界维度      supported -> unresolved  (已降级)
世界佐证      实测 1/2
为什么降级：
  [world] run_input_changed  实测 #2 的上游 #1 变了：复现/out/unet_small.keras
```

改回去（哈希恢复原样），它自己又上来。**状态不存，每次读都重算**——存下来的状态会撒谎，而撒谎的状态比没有状态更危险。

**程序不判断两份来源是否真的独立**，也不判断「我跑过」能不能代表「学界认可」——那是人的判断。它只保证：你说「这是真的」的时候，手上得有一份能复核的东西，且那份东西没被改过。

`status` 会把两类依据分开报，别把「我跑过一次」当成「别人也这么说」：

```
世界佐证      独立来源 0/0，实测 2/2
```

还有一条边界，验证时撞出来的：**`实测 1/2` 仍然是 supported**。因为 run #1 还在，而 run #2 才是支撑「MAE 和常数基线一样」这个关键结论的那条。工具数的是「有几条依据」，不是「关键依据在不在」——它不知道哪条 run 支撑主张的哪一部分。看到分母掉了，得自己去确认掉的是不是关键那条。

## 动手之前，问一次

前面所有校验都卡在同一个位置：**归档**。但真正出事的地方在更前面——AI 直接改文件、直接删目录、直接往外发。那个位置一个检查点都没有，因为它发生在有人想到要校验之前。

`guard` 把执法点往前提一格。它不给每个领域写一套「专不专业」的判断标准（写不完也测不准），只拦四类机械可判的事：

| 拦什么 | 为什么 | 决策 |
|---|---|---|
| 直接写 `entries/<id>/entry.md` | 绕过版本校验和入库闸门 | deny |
| 动 `entries/<id>` 这个目录（任何非读动作） | 依赖它的条目会断链，而且删除不可逆 | deny，指向 `retire` |
| 目标跑出工作区 | 工作区外工具没有任何保护，不该假装有 | ask |
| 删 / 发布 / 强推 / 截断 | 没有第二次机会 | ask |
| 内容命中条目里学到的坑 | 知识攒下来就是为了这时候用 | ask + 指出行号 |
| 内容里有本机路径、邮箱、手机号、身份证号、疑似密钥 | 写出去就收不回来 | ask |

**动作名先分三档，不是两档**：`read` / `delete` / `publish` / 其余一律 `write`。

`read` 这一档必须存在。没有它的时候，读被归进 write，而 `entry.md` 的保护条件是「kind 是 write」——于是**读一个条目文件也会被 deny**。一个只会喊「不许碰」的闸门，第一次误伤之后就会被关掉，然后什么都不拦。

删除那一档要按「非读」判，不能只认 `delete`。早先只拦 `kind === 'delete'`，而删除正则只认出 delet/remov/unlink/eras/truncat/drop/rm——`purge`、`wipe`、`clear`、`destroy` 落到 write 分支，而 write 分支只管 `entry.md`、**不管条目目录**，于是四个删除语义的动词全部放行，整条主张就这么没了。

```bash
proofline guard --target 复现/new_normalize.py --action write --content /tmp/new.py
```

```
guard: ask
  [ask] rule_hit  2026-11-21-minmax-hurt-by-outliers：先看幅值分布有没有离群点；有就改用分位数裁剪
      → 第 2 行：X_train = (X_train - X_min) / (X_max - X_min)
```

这是这个工具里**唯一一个能影响「还没发生的事」的地方**。其余功能都是事后核账。

### 它仍然是个被调用的命令

这件事试过了，结论是硬碰硬：

**WorkBuddy 这一版没有「工具调用前执行外部程序」的接口。** `settings.json` 里只有声明式的沙箱规则（路径 + read/write/delete 三档），没有 PreToolUse hook。所以 `guard` 挂不到 `Write` / `Edit` 之前，只能被调用。

它能被挂上来的方式只有两种：

1. **AI 自己每次动手前调一次**（`AGENTS.md` 第十条，是纪律不是机制）；
2. **宿主的沙箱规则**——但那不能执行外部命令，只能表达静态路径规则。

这不是它的设计缺陷，是宿主能力的天花板：**一个 CLI 拦不住没有义务调用它的进程。**

判断尺度和别处一样：拿不准一律 `ask`，不 `allow`。误报的代价是多看一眼，漏报的代价是「以为查过了」。

### 所以它的真实拦截半径

拿项目里 105 个真实文件跑了一遍（`--target` + `--content`，相当于「我要把每个文件写成现在这样」）：

```
allow 67   ask 12   deny 26
```

- **26 个 deny 全是 `entry.md`**——正确。那些文件不该用 `Write` 改，该走 `set` / `run` / `corroborate`；
- **12 个 ask 里 9 个是真命中**：这个项目的脚本确实没滤波、确实用 min-max，规则如实报了；
- 剩 3 个 privacy，2 个是真路径（脚本里的盘符、报告里的解释器路径），1 个是脱敏占位符被误判。

关键在于：**这 26 次 deny 在正常流程里不会发生**——因为正常流程走 CLI，而 CLI 不调用 guard。只有当有人（或 AI）抄近路直接改文件时，它才会响。这正是它该响的时候。

### 实测撞出来的三个 bug

不真在真实路径上跑一遍，这三个都发现不了：

**一、保护正则在真实目录结构下完全失效。** 原来写成 `^entries/...`，而真实结构是 `workspace/ppg2abp/entries/...`。从项目根跑一条都拦不住，从条目目录跑又把源码判成「工作区外」。单元测试用的是扁平路径，正好测不到。

**二、规则把散文当代码扫。** 一篇讲 PPG 的论文命中「PPG 要先滤波」，README 里写了 `rm -rf` 四个字就命中「危险删除」。23 个文档里 12 个被命中，全是假阳性。已限定规则只对代码扩展名生效。

**三、`guard` 和 `audit` 对同一份文件给出相反结论。** 测试夹具里的假路径加了 `// audit-ignore`，`audit` 认，`guard` 不认。两个检查器打架，人只会两个都不信。已让 `guard` 认同一套豁免。

## 候选从哪来

判定层只决定「该不该说」，它不生候选。所以还需要一层：**从产出物里读风险。**

```bash
proofline scan <项目目录> --project ppg
proofline scan <项目目录> --project ppg --advise --commit   # 一条命令走完
proofline rules                                            # 看有哪些规则
```

它只看代码，不猜意图。命中之后给出文件名和行号——指不出位置的提醒，人没法核，也没法改。

### 五条规则

| 规则 | 判据 | 分级 |
|---|---|---|
| `destructive-cleanup` | `rm -rf` / `shutil.rmtree` / `os.remove` | 致命 · 不可逆 |
| `timeseries-random-split` | `train_test_split` + 文件里有时间语义 + 没有 `shuffle=False` | 失真 |
| `filter-phase-shift` | `butter`/`cheby`/`iirnotch` + `lfilter`，且没有 `filtfilt` | 偏离惯例 |
| `unseeded-random` | 用了 `np.random.` / `random.` 但没有 `seed` / `default_rng` | 偏离惯例 |
| `hardcoded-abs-path` | 盘符绝对路径，或以 /home 、/Users 开头的路径 | 偏离惯例 |

加上库里长出来的规则，实测 1 个项目文件能同时命中两类——一类内置、一类来自某条具体知识。

实测（一个故意写坏的管线）：

```
扫描 2 个文件，5 条规则，命中 5 类风险

[致命 · 不可逆] destructive-cleanup  命中 1 处
    clean.sh:2  rm -rf ./cache ./build
[失真] timeseries-random-split  命中 1 处
    pipeline.py:9  train_test_split(df[["ppg"]], df["bp"], test_size=0.2)
...

—— 该不该说 ——
[硬停] destructive-cleanup        irreversible
[正文] → 清单 filter-phase-shift   high_cost · turn_limit
[记账] unseeded-random            low_cost
[正文] → 清单 timeseries-random-split high_cost · turn_limit
[记账] hardcoded-abs-path         low_cost
```

### 规则是两层：内置的 + 库里长出来的

内置那 5 条是手写的。除此之外，**每条知识都能自己长出检查**：

```yaml
checks: [{
  "type": "pattern",
  "present": "(PPG|ppg|脉搏波|光电容积)",          # 代码里出现这个
  "absent": "butter|lfilter|filtfilt|savgol",       # 且全文没有这个
  "level": "偏离惯例",
  "cost": "high",
  "reversible": true,
  "action": "PPG 数据先做高通或带通滤掉基线漂移"
}]
```

`scan` 会把它变成规则去扫代码，命中时报出**这条知识本身**：

```
[偏离惯例] entry:2026-11-21-ppg-needs-filtering#1  命中 2 处
    来自库：PPG 信号必须先滤除高低频噪声与基线漂移，才能用于后续特征提取
    依据：「需要滤波去除高低频噪声和基线漂移等影响」
    preprocess.py:5  sig = df["ppg"].values
    → PPG 数据先做高通或带通滤掉基线漂移与高频噪声，再进特征提取
```

**这是这套东西唯一会自己变强的地方**：你学到一个坑，入库一次，以后它自动帮你盯着。

条目删了，规则跟着消失——规则不另存一份，免得和知识对不上。

```bash
proofline rules              # 看内置几条、库里几条
proofline scan <目录> --no-library   # 只用内置规则
```

#### 写不出正则就写词

`pattern` 要正则。但卡住人的不是语法，是「为了记一个坑，还得会写正则」——第一轮 22 条条目里只有 3 条写了 `checks`，就是这个原因。

所以有第二种写法：

```yaml
checks: [{
  "type": "term",
  "present": "MinMaxScaler",     # 普通字符串，内部转义，不当正则
  "absent": "RobustScaler",
  "level": "偏离惯例", "cost": "low", "reversible": true,
  "action": "先看幅值分布有没有离群点，有就改用分位数裁剪"
}]
```

判定完全一样，只是 `present` / `absent` 按子串查。`MinMaxScaler()` 在 `term` 里就是带括号的那串字，不会因为括号被当成分组。

还是想不出该查什么词，就让工具把候选摊开：

```bash
proofline draft <id>
```

```
2026-11-22-code-global-normalize 里出现过的代码标识符（挑一个当 present）：

  min_ppg                  引文
  X_train                  引文
```

它只抽**引文和正文代码块**里的标识符——那两处出现的词，一定是这条主张真正在说的东西。从散文里抽会抽出「血压」「模型」这种。

草稿里的 `action` 故意留空，空 `action` 会被校验拒掉。一条说不出「检出后该怎么办」的检查，入库只会变成噪音。

#### scope：这条规则只在哪些文件上生效

不填就是全库生效。有些规则该限定范围，比如「预处理脚本必须用 `filtfilt`」——它只该在预处理代码上响，不该在画图脚本上响。

```yaml
checks: [{ "type": "term", "present": "lfilter", "absent": "filtfilt", "scope": "preprocess|filter" }]
```

`scope` 是路径正则，匹配文件相对路径。拿不到文件路径时**一律不命中**——范围未知就不能假定生效。

**但别拿它压噪音，我在这上面栽过一次。** 实测发现有 8/9 个脚本命中「PPG 要先滤波」，我判断这是误报，就给那条规则加了 `scope`。结果 `_scaled.py` 掉出了扫描范围——它确实在做 min-max，只是文件名里没有 `normaliz`。

两件事都错了：那 8 个命中**不是误报**，这个项目就是普遍没滤波（这恰好是复现时发现的问题之一）；而用文件名判断「这个文件该不该扫」本身不可靠。

判断标准：**如果一条规则的真假取决于代码内容，别用 scope；如果取决于「这是不是那类文件」，才用 scope。** 前者用 `present`/`absent` 就够，加 scope 只会漏。

### 写规则的三条纪律

**宁可漏，不可误报。** 误报一次，后面所有提示都会被当成噪音。所以每条规则要求两个以上条件同时成立，不靠单一关键词——比如时序随机划分，必须同时有 `train_test_split`、时间语义、且没写 `shuffle=False`。

**必须给得出下一步动作。** `action` 为空的规则不该存在，判定层会把它判成 `silent`，等于白写。

**说得出「怎么观察」。** 每条规则要能指出文件和行号。

### 这一步的局限，直接说

**覆盖率还是低。** 22 条条目里 4 条有 `checks`。`term` 和 `draft` 把门槛降了一截，但没解决根本问题：**一条结论要能被机器检查，它本身就得长成「可判定的形状」**。像「模型没学到波形」这种结论，只能靠人再看一遍波形相关性，写不出一个查什么词的条件。

所以 `checks` 永远是子集，不是全集。指望它覆盖所有条目，等于指望所有知识都能被关键词表达。

**draft 只会摊候选，不会替你选。** 它把标识符捞出来，挑哪个、配什么反例、`action` 写什么，全要人做。这里故意不做自动填——填错了会变成一条「看着合法、实际没人想说下一步」的检查，入库能过、扫描会响，但响了不知道该干什么，比没有更坏。

还有一个已知的自我命中问题：`rules.js` 里写着 `rm -rf` 的正则字面量，扫自己会被自己命中。规则匹配代码，代码里写规则，这类回环迟早要处理。

## 话题：同一件事，不许互相不知道

条目多了之后，同一个问题上会并存好几种说法，而它们彼此不知道对方存在。

`topic` 就是给这件事一个名字：

```yaml
topic: ppg.preprocess
```

然后：

```bash
proofline review                 # 按话题并排
proofline review --topic ppg.preprocess
```

```
ppg.preprocess   4 条
  [标准] PPG 信号必须先滤除高低频噪声与基线漂移，才能用于后续特征提取
        可引用 · 世界=unresolved · 2026-11-21-ppg-needs-filtering
  [标准] PPG 预处理不止滤波，标准流程是滤波、周期划分、信号质量三步
        可引用 · 世界=unresolved · 2026-11-22-ppg-preprocess-three-steps
  [标准] PPG2ABP 对每个 T 秒片段只做最小预处理（如滤波），不做周期分割
        可引用 · 世界=unresolved · 2026-11-22-ppg2abp-minimal-preprocess
```

### 它是什么，不是什么

**是**：保证同一话题下的多种说法**不会互相不知道对方存在**。

**不是**：矛盾检测。工具读不懂语义，判不了「必须先滤波」和「只做最小预处理」哪句对。

所以它挂的旗子只覆盖**状态层面**的不一致，不覆盖语义：

| 旗子 | 判据 |
|---|---|
| 结论不一 | 同一话题里，世界维度一个是 `supported`、一个是 `unresolved` |
| 可用性不一 | 一条能引用、一条不能 |
| 层级混用 | 一条 `标准`、一条 `线索`（线索层永远不能当依据） |

`check` 会把这些旗子打成提示，**但不改退出码**——数据没错，只是需要人看一眼。

### 一条经验

我们自己的案例（综述说预处理含滤波 / PPG2ABP 只做归一化）**一个旗子都没挂上**，
因为两条都是 `unresolved`、都 `标准`、都能引用。

但把这四句并排放在一屏里，人一眼就看出问题了。

**所以这个功能的价值在「并排」，不在「报警」。** 指望它自动发现矛盾，会失望。

### 但「并排」可以做得更好：把数值排成表

上面那个案例暴露了一件事：并排列的是**句子**，不是**数**。八条主张读下来，读到第三句就忘了第一句说的是几。

给条目加一个可选字段：

```yaml
value:
  metric: pm25.annual          # 同一个指标才比
  number: 35
  unit: µg/m³
  subject: 中国                 # 必填：这个数是谁的
  scope: GB 3095-2012 二级      # 必填：哪个规定的数
  effective_from: 2016-01-01    # 可选
```

`subject` 和 `scope` 差一个层级：前者说「谁」，后者说「哪个规定」。分开是因为用途不同——`subject` 用来把表分组，`scope` 用来判断两个值是不是同口径。

`review` 就会在条目列表**之前**插一张对照表：

```
指标 pm25.annual（µg/m³） · 8 条带数值 · 5 个不同值
  中国
        35  GB 3095-2012 二级
  WHO
        35  2005 过渡目标 Ⅰ阶段
        35  2021 过渡目标 IT-1
        10  2005 指导值 AQG
         5  2021 准则值 AQG
  欧盟
        25  现行指令 2008/50/EC
        10  修订指令 2024/2881 · 2030-01-01 起
  美国
         9  EPA 一级标准

同一个指标，5 个不同的值。
35 出现 3 次，10 出现 2 次——看 scope 那一列，它们不是一回事。
```

**按主体分组是这个字段的主要用途。** 平铺一排数字看不出「谁是同一个人说的」；分组之后，「WHO 有四个数（两级台阶 + 两个终点）」「欧盟有两个数（现行 25 / 2030 年 10）」一眼就能看见——而它们恰恰是最容易被当成一个数的。

**它不判断谁对。** 中国 35 和美国 9 不是矛盾，是两个辖区各自的规定，工具无权说谁错。它做的是让这些数并排站着。

### `scope` 为什么必填

不写清「这个数适用于谁」，这个数就没法跟别的数比。而**写 scope 这个动作会逼人想一件事**：我说的是中国的限值，还是 WHO 的过渡目标？

想清楚之后，很多「矛盾」自己就消失了——因为它们本来就不是一件事。

### 能下判断的，必须说清「不能用来干什么」

```yaml
not_for:
  - 不能说这个模型学不会波形——只是 1200 段 2 epoch 跑不出来
  - 不能推广到别的任务或别的规模
```

`status` 里它紧跟在「能下判断」后面：

```
能引用        是（来源确实这么说过）
能下判断      是
不能用来      不能说这个模型学不会波形——只是 1200 段 2 epoch 跑不出来
              不能推广到别的任务或别的规模
```

**为什么放在这儿**：引用的人先看「能不能用」，看到「是」就会用。边界必须在同一屏、同一行附近，放页脚等于承认它不重要。

**门槛跟着杀伤力走**：能当依据去否定别人的主张，缺边界就不判 `decisive`；本来就不可引用的主张，不写也行——推过头最多自娱自乐。

**这不是 hard_fail，是可用性判据。** 试过硬失败，撞上死锁：一条老条目同时缺 `basis` 和 `not_for`，`set basis` 被 `not_for` 挡、`set not_for` 被 `basis` 挡，两个都补不上。

更根本的是：**「能当依据却没说边界」不是数据错误，是质量缺陷。** 数据错误用报错挡（挡得住这一次），质量缺陷用机制挡（挡得住以后每一次）。所以判在 `deriveStatus` 里，缺边界 → `decisive: false`，`boundary_missing: true`。

### 判断档也有链：`derived_from`

一条判断是怎么来的？两种很不一样的来源：

- 「把三条可引的事实摆在一起，得出它们不在同一条时间线上」
- 「我觉得主因是训练量不够」

都是判断，都不能直接引用。但第一种，**你只要去核那三条就能自己得出结论**；第二种，你只能信我或者不信我。

```yaml
basis: 判断
derived_from: ["2026-11-22-mee-cites-eu-10", "2026-11-22-eu-current-25"]
```

`status` 会把链算出来：

```
依据          判断
推理链        3/3 条依据全部可引用（完整）
能引用        否
```

推的那几条里有掉队的，它自己会说：

```
推理链        3/4 条依据可引用——推的那几条里有掉队的
```

**注意最后那行「能引用 否」没有变。** 推理链完整只说明「推的那几条站得住」，不说明「这个结论是读来的」。这条线不能松——一松，所有判断都能靠凑三条依据变成可引用。

`derived_from` 只在 `basis=判断` 时允许。条目档写它是错的：它有原文，不需要「从哪几条推的」。

### 唯一会判「矛盾」的情况

同 `metric` + 同 `unit` + 同 `scope` + 同 `effective_from`，但 `number` 不同：

```
✗ 同口径不同值：pm25.annual · 欧盟 现行指令 2008/50/EC
    25 µg/m³  2026-11-22-eu-current-25
    10 µg/m³  2026-11-22-eu-somewhere-else
  口径说是同一件事，值却不一样——这两个数不可能同时成立。
```

这条线划得很小心。**工具能说「不可能同时成立」的场合极少**——越少越好，说一次得算一次。不同辖区、不同年份、不同性质的数，一律不判，摆出来让人看就够了。

## 来源：这个库靠什么撑着

条目里有 `source_uri`，但那是每条各写各的字符串。于是回答不了两个基本问题：
**我到底依赖了几个来源？这篇不可信，它下面挂了哪几条？**

```bash
proofline sources
```

```
4 个来源，支撑 6 条主张

[在用] 科学技术与工程 2024, 24(5): 1756-1774
        支撑 3 条 · OCR
[在用] https://arxiv.org/abs/1706.03762
        支撑 1 条 · 原文
```

### 为什么不给「删」，只给「弃用」

删掉一份材料，从它长出来的主张就**失去证据，而且不可恢复**——快照参与哈希，删了就是删了。
这不是缺陷，是这套东西的核心代价：**可核与可删只能选一个**。

所以改成来源级判断：

```
proofline deprecate "某篇论文" --reason "期刊已勘误"      # 只看后果，不改任何东西
proofline deprecate "某篇论文" --reason "期刊已勘误" --confirm   # 真的弃用
proofline restore   "某篇论文"                          # 撤回
```

不带 `--confirm` 时它只把后果摆出来：

```
它支撑       3 条主张
改成「弃用」之后：
  这 3 条  → 降级为不可引用
  库里剩余可引用  → 3 条
这么做的好处：不再把这份材料当依据。
代价：上面这些主张失去证据，要么重新找来源，要么接受它们变成「只有印象」。
```

**工具算后果，好坏由人判断。** 弃用必须给理由——没理由的弃用，三个月后没人记得为什么。

降级只发生在读的时候，不覆盖条目里人写的 `evidence_status`：判定只能由人改。

### 条目级：`retire`，不是 `delete`

来源能弃用，条目原来不能——这是上一版的一个洞。一条条目记错了、或者只是当时试试，只剩下 `rm -rf` 一条路，而它绕过所有闸门。

```
proofline retire <条目> --reason "为什么"            # 只看后果
proofline retire <条目> --reason "为什么" --confirm  # 真的退役
proofline retire <条目> --by <接替者> --reason ... --confirm
proofline retire <条目> --undo                      # 撤回
```

退役写入一个字段：

```yaml
deprecated: {"at":"2026-11-22","reason":"当时把论文的说法记成了代码事实","superseded_by":"2026-11-22-xxx"}
```

**它改的是可用性，不是证据。** 这是这一节最要紧的一句话：

```
状态         已退役（2026-11-22）：当时把论文的说法记成了代码事实
能引用        否（不是撑不住，是我们决定不再用它）
能下判断      否（同上）
来源维度      supported -> supported      ← 没降级
世界维度      unresolved -> unresolved    ← 没降级
```

`evidence_effective` 故意不变。原文说过就是说过，这件事不会因为我们决定不用它而改变。混在一起改，会让人以为证据失效了，于是去补一份新证据来修一个本来不需要修的东西。

**退役也不进 `reasons`。** 第一版把它 push 进去、维度标成 `evidence`，于是 `status` 出现这一屏：

```
来源维度      supported -> supported
状态         已退役……
为什么降级：                                    ← 上面刚说没降级
  [evidence] entry_retired  已退役……
```

一屏之内自己否定自己。更糟的是 `dimension: evidence` 会让任何按维度统计「证据问题」的下游，把「我们决定不用了」算成「证据出毛病了」——这正好是退役设计要避免的那个混淆，只是从字段搬到了理由的维度标签上。

**字段写了就算退役，写残了也算。** `deprecated: {}`、`deprecated: []`、`deprecated: "2026-11-22"` 都按退役处理，只是额外标 `retired_malformed`：

```
状态         已退役，但这条记录残缺（缺 at / reason）
             字段写过但写残了——按退役处理，因为写残的退役不该变成可引用
```

只判类型的第一版有个要命的性质：**想退役却手写残了的条目，会被当成没退役，继续可引用**。这是「失败路径静默通过」的教科书形状。方向定死：坏数据只能让条目更不可用，不能更可用。

**为什么不是改 `claim`**：改 claim 是把错的抹掉，抹掉之后没人知道你错过。退役留着原话，只摘掉可用性。

**为什么不是 `delete`**：删了别人的 `prereq` 就断链，而且不可恢复。退役之后链接还在，指向的东西明确标记着「不能用了」——`check` 会把这个情况列出来：

```
前置指向已退役的条目（1 处，不影响本次成败）：
  2026-11-22-b  →  2026-11-22-a
  链没断，但指向的东西已经不能用了——换前置，或者撤销那条的退役。
```

`check` 不会因此判失败。数据本身没坏，只是有一条链指向了不再使用的东西——那是需要人看一眼的事，不是错误。

**接替关系也查。** `retire --by` 只在写入那一刻看目标在不在，之后目标被删、被退役、或者两条互相接替，它一概不知道：

```
接替关系有问题（2 处，不影响本次成败）：
  2026-11-22-a  →  2026-11-22-b（接替者自己也退役了）
  2026-11-22-c  ⇄  2026-11-22-d（互相接替，谁都没接上）
  「由谁接替」是给人指路的。指到一个不可用的地方，不如不指。
```

环要排在「接替者也退役了」前面判——互相接替的两条一定都退役了，先判退役就会把它说成两个独立的「接替者也退役了」，而真正的问题是它们指回了对方，那是结构错，不是状态变化。

## 知识分三层：学科 / 技术 / 语言

原来 `kind` 只有「基础 / 核心 / 工具」——那说的是**重要性**，不是**知识性质**。
结果课程地图只画得出学科：数学、电路、信号。而真正动手要用的
Python、C、命令行、英语，一条都进不来，因为它们不是「课程」。

拆开之后：`kind` 说这是什么（学科/技术/语言），`tier` 说有多要紧。

| 层 | 回答的问题 | 怎么衡量 |
|---|---|---|
| **学科** | 为什么这么做 | 课程状态（在修/已修/未修/缺口） |
| **技术** | 会不会动手 | 等级 L1–L4（认得 / 会用 / 会调 / 会选） |
| **语言** | 读不读得动原文 | 同上，按「能读到什么程度」定刻度 |

### 技术为什么用等级，不用「学过没学过」

「学过 C 语言」和「能改得动 MCU 采集循环」是两件事。四级刻度：

```
L1 认得   看得懂别人的代码，能改一行跑起来
L2 会用   能照着文档拼出自己需要的流程
L3 会调   出错能定位到哪一步、为什么
L4 会选   知道什么时候不该用它，能比较替代方案
```

每个技术域的这四行**写在结构里**（`knowledge-map.json` 的 `levels`），
因为「这个项目怎么算会」是项目的事；我的等级写在 `progress.json` 的 `skills` 里。

```json
// 结构：这个块要求 Python 到 L3
{ "id": "model", "needs": ["prob", "linalg", "python"], "needLevels": { "python": 3 } }

// 个人：我现在 L2，估的
{ "domain": "python", "level": 2, "estimated": true, "note": "跑过别人的脚本" }
```

缺口判据因此变成 **「要求几级 vs 现在几级」**，不是「学过没学过」。
学过课但到不了 L3，照样是缺口。

`estimated: true` 会显示成「（估）」——由我按证据估的，不是你自己打的分。

### 备选不是主线

C++ 和俄语标了 `role: 备选`：**留着位置，不是现在要学**。

- C++：只在要用现成 C++ 库、或某段慢到必须优化时才需要
- 俄语：目前库里**零条**俄文来源，没有任何主张依赖它。列出来是为了将来真遇到时不用改结构

所以「备选」不参与「学了用不上」的检查，也不会变成缺口。

### 代码也是一种来源（一条命令）

```bash
proofline import <id> --code <代码目录> \
  --claim "..." --quote "..." \
  --url https://github.com/owner/repo --title "某某仓库"
```

它自己会：

- 收源码（`.py .js .ts .c .h .cpp .m .go .rs .jl …`）与依赖清单（`requirements.txt` / `package.json` / `pyproject.toml` / `Makefile` …）
- 跳过 `node_modules` `.git` `__pycache__` `.venv` `dist` `build` 这类目录
- 单文件超过 512 KB 跳过，**但记在 `_meta.skipped` 里**——不许静默假装读过
- 按路径做数字感知排序，`2.py` 排在 `10.py` 前面
- 标成 `source_kind: 项目`、`source_extraction: 原文`（直接读源码，中间没有有损转换）
- 没有 `--url` 时用 `code:<目录名>` 当标识——它明确不是 URL，也不冒充 URL

以前要把代码入库，得手搓一个假论文目录（`metadata.json` + 拼接 `PAPER.md`），八次里错三次。那层不该由人来做。



技术域的「要到 L3 具体会什么」，如果只靠我推，就是空话。所以代码仓库也能入库：

```bash
# metadata.json 里写 type: github + url，导入器会记成「项目」而不是「论文」
proofline import 2026-11-22-code-keras-layers --paper <代码目录> \
  --claim "网络只用这几类 Keras 层：..." \
  --quote "from keras.layers import Input, Conv1D, ..."
```

`source_kind` 因此有了「项目」这一档：来源是代码时，`source_original` 不必再要求一份「原件 PDF」。

代价是：**代码的事实要靠 grep 确认，不能靠印象。** 这一轮就翻车了两次——
我以为要用 WFDB 读 MIMIC（实际是 h5py 读 .mat），以为要 scipy.signal 滤波（全仓库没有滤波）。
两条都已经按代码改掉，并把「猜错了」写进 `basisNote`，免得以后当成结论用。

### 一条自我校准

加了语言层之后，程序自己报出：**「英语没有出口」**——
图上根本没有一块能力需要英语。

那是真的缺了：这个项目的每一手来源都是英文，而「读文献」这块能力当时不在图上。
补上之后它挂在「文献调研」下面，英语就从死路变成了 L2 需求。

### 依据分三档，不是两档

| 依据 | 含义 | 谁能核 |
|---|---|---|
| **条目** | 库里有能定位的原文 | 逐字搜一遍 |
| **实测** | 自己跑出来的，附脚本 | 重跑一遍 |
| **判断** | 按项目推的，没原文也没跑 | 谁也核不了，只能当面问 |

原来只有「条目 / 判断」两档，于是「我跑过，它确实这样」只能算「判断」——
和「我猜的」挤在同一格里。加上 `实测` 之后，能力块可以带 `run` 指向复现脚本：

```json
{ "id": "evaluate", "basis": "实测", "run": "复现/verify_fold.py" }
```

`实测` 但没给 `run` 会被警告——要求别人相信，就不是实测。

## 课程地图：两份数据，两个问题

```
knowledge-map.json   做这件事需要什么知识   —— 客观、通用、跟谁做无关
progress.json        我现在到哪了          —— 个人、会过期
```

一开始我把它们合成一份，图就变成了「我这学期的快照」：课名是本校叫法，状态是本学期状态，下学期一来整张图过时。

分开之后有一条**可验证的标准**：

> 把 `progress.json` 删掉，图还得画得出来。

画不出来，说明结构里掺了私货。

```bash
proofline map          # 生成 课程地图.html
```

页面上一段话把两者分开写：

- **结构**来自项目：需要哪几块能力、每块靠什么知识。任何做这个项目的人都一样。
- **颜色**来自 `progress.json`：我这门课学到哪、卡在哪。删掉就只剩结构。

三层内容：能力块（标 `条目`/`判断`）、知识域（按先修缩进，标 `背景`/`主线`）、缺口（只有个人进度才有）。

「这个项目用不上物理」是**结构判断**，所以写成 `role: 背景`，不放在个人进度里——把它放进个人进度，等于让"不相关"随人而变。

## 知识地图

`prereq` 字段说「学这条之前要先懂什么」。地图按它长成一棵**缩进树**，不是网状图。

理由：prereq 本质是偏序，不是任意连接。力导向图 20 个点就成一团毛线，而且不回答「该先学哪个」。缩进树直接回答顺序。

三条规矩：

- **卡壳点自动标**，不用人画：红＝有阻塞缺口，黄＝只到「有人说过」，绿＝可判定
- **孤点单列**：既没前置也没人依赖的，不混在树里假装有位置
- **断链和环必须报**：前置指向不存在的条目、或互相依赖成环，都写在页面上。一个漂亮但藏了断链的图，比不画更糟

```
知识地图
 · PPG 预处理不止滤波，标准流程是滤波、周期划分、信号质量
   · PPG 信号必须先滤除高低频噪声与基线漂移          ← 缩进 = 前置关系
 · PPG2ABP 用 MIMIC-III 的同步 PPG/ABP
   · PPG2ABP 只做最小预处理
     · PPG2ABP 做全局 min-max 归一化
     · 近似网络用 MAE 当损失比 MSE 更好

还没接线：7 条
```

孤点比连着的多，说明这张图现在还是一堆散件。**填 prereq 就是在把它接起来。**

## 两种看法：静态导出 与 本地服务

```bash
proofline view                 # 存成一个文件，发给别人、打印
proofline serve                # 起个本地服务，浏览器打开就是现在
```

差别只有一条：

| | `view` | `serve` |
|---|---|---|
| 是什么 | 某一刻存下来的快照 | 每次打开现算 |
| 用途 | 发人、归档、打印 | 自己看当下的库 |
| 脚本 | 零 | 零 |

**都不是"文件一变页面自己跳"。** 那是即时，不是实时。

自动刷新会在你读到一半时把页面冲掉——那不是帮忙，是打断。想更新，按一下刷新，重算的就是此刻。

两条都只读、都只绑本机、都不做静态文件服务。

## 证据册：一份只读的页面

```bash
proofline view            # 生成 证据册.html
```

三个部分：来源清单、知识树（按来源分组，点开看引文与卡点）、进度。

三条规矩：

1. **只读。** 没有写操作，不连服务。
2. **状态由 CLI 算好再渲染。** 页面不做任何计算——否则又会变成「同一事实两处算」。
3. **不含一行 JS。** 展开靠 `<details>`，坏不了，也不留脚本。

它不是操作台。写入方是 AI，做操作台会诱导人直接改判定，而判定是唯一必须由人负责的东西。

## 什么时候该开口

库有了，还得知道「现在该不该说话」。不然接进任何平台的结果都一样：模型看到问题顺口提一句，或者干脆不提——前者是噪音，后者是沉默，两个都不叫主动。

`advise` 就是这一层。它不产生内容，只做决定。

```bash
proofline advise --project ppg --candidates cand.json --commit
proofline log ppg
```

`candidates.json` 是候选提醒，谁给的都行（模型、规则检查、人）：

```json
[{
  "key": "random-split-timeseries",
  "level": "失真",
  "cost": "high",
  "reversible": true,
  "action": "把 train_test_split 改成按时间切，前 80% 训练"
}]
```

### 四条判据

1. **不可逆 → 一律硬停。** 数据删了、板子烧了、论文投出去了，没有第二次。
   **不写 `reversible` 字段就按不可逆处理**，并在原因里标 `irreversible_assumed`。
   缺省朝安全方向偏——宁可他多按一次确认，不能因为少写一个字段就悄悄放过。
2. **代价大 → 必须说。** 不猜「他自己能不能发现」——报错不等于他理解那是个大问题。
3. **落不到动作 → 不说。** `action` 为空就不开口。「注意数据泄漏」没下一步，不算提醒。
4. **同一条不重复。** 说过且没解决，退到清单，不再进正文。

### 强度和通道是两件事

| 强度 | 含义 |
|---|---|
| `hardstop` | 必须回应才能继续，只给不可逆 |
| `inline` | 一句话飘过去，不打断流程 |
| `log` | 完全不打扰，只记账 |
| `silent` | 不说 |

通道分 `body`（正文）/ `list`（风险清单）/ `none`。

分开的理由：已问未解的风险每次都得「在场」，但每次在正文念一遍就会被整段跳过。让它待在清单里，正文只在新证据出现时提。

### 它是一个队列，不是一次判断

同一批候选连跑三轮（真实输出）：

```
第 1 轮  [硬停] raw-data-wipe          irreversible
        [正文] → 清单 random-split      high_cost · turn_limit
        [正文] → 清单 zero-phase        high_cost · turn_limit

第 2 轮  [正文] → 清单 raw-data-wipe    irreversible · already_open · kept_in_list
        [正文] random-split            high_cost
        [正文] → 清单 zero-phase        high_cost · turn_limit

第 3 轮  [正文] → 清单 raw-data-wipe    irreversible · already_open · kept_in_list
        [不说] random-split            high_cost · already_open
        [正文] zero-phase              high_cost
```

一轮只在正文说一条，其余在清单里排队，下一轮轮到。**不轰炸，也不漏。**

**一个例外：不可逆不受这条限制。** 一轮里有三个不可逆，就三条都硬停。
安全的关键风险不该因为「今天说够两条了」被压掉——配额只压能降级的那类。

### 两个容易搞错的点

**配额压不掉不可逆。** 每天最多说几次、冷却多久，只作用于非不可逆的提醒。

**清单不等于说过。** 只在清单里出现过的，下一轮还能升级进正文；只有正文说过的才算说过。这两件事混成一个状态，就会出现「被挤到清单、从此永远沉默」。

### 日志是 append-only

存在 `<entries>/.log/<project>.jsonl`，一行一个事件，**不删不改**。

状态（说过几次、有没有解决）每次读的时候重放算出来，不存。理由跟条目一样：存下来的状态会撒谎。

## 四种校验结果

| 状态 | 含义 | 会写回吗 |
|---|---|---|
| `pass` | 干净 | — |
| `fixed` | 有机械问题，已修 | 是（`--fix` 时） |
| `dirty` | 有机械问题，没修 | 否 |
| `hard_fail` | 证据对不上，或形状废了 | **否，一个字都不写** |

分界线只有一条：**这个检查能不能写成代码**。

空白、大小写、日期补零、id 和目录名不一致——机械问题，能修。
引文在不在原文里——也是机械检查，但它一不过，这条证据就是假的，只能作废。

有一条不设例外：**判定字段永不自动修**。写 `支持` 不会被猜成 `supported`，直接 hard_fail。猜一次，这条判定就变成我们替作者下的结论了。

## 两级可用性

不是「能用/不能用」两档，混成一档会把参考架构类条目全判死。

| 级 | 条件 | 用来干什么 |
|---|---|---|
| **能引用** | 来源维度 `supported`（引文已定位） | 说明「有这种说法」，触发去查 |
| **能下判断** | 还要 标准层 + 世界维度有结论 | 判「你这做法业余」 |

一条「只有一家这么做」的参考架构，能引用，但不能下判断。这是对的。

---

## 它不做什么

- 不判断你的主张对不对（那不是代码能判的，交给 `evidence_status` / `world_status` 两个字段）
- 不抓网页、不解析视频（输入是本地文件；抓取是另一件事）
- 不做检索算法（30 条用 grep 就够，上千条再说）
- 不做界面（入口是 AI 对话，不是窗口）

## 三条踩过的坑

**一、算指纹要排除抓取时间。** 抓取时间是观察行为，不是被观察对象的一部分。算进去了，同一篇文章抓两次指纹就不一样，「内容变没变」永远判断不了。

**二、清洗要跑到不动点。** 剥掉嵌套结构，可能把剩下的部分重组成一个新的、看起来合法的结构。（`[cl[real]aim]` 剥一次变 `[aim]`。）任何「删一部分」的操作都有这个问题。

**三、真实来源不干净。** 这条是拿一篇真论文试出来的，一开始没想到：

OCR 会把「重要参考数据」断成「重要参考 数据」。人写引文时不会写那个空格，于是自然书写的引文**定位不到**——不是因为引文错，是因为中间被塞了一个空格。全角字母（`Ｒesearch`）同样会错位。

所以**宽松匹配**分两级：先按空白归一找，找不到再去掉全部空白找。加上最初的逐字匹配，引文定位一共三级（`exact` / `normalized` / `space-insensitive`）。命中的是哪一级会记在 `mode` 里。

但有些东西算法救不了：OCR 认错的字。`进行` 被断成 `进行 `，去空白能救；`对比` 被认成别的字，就救不回来。这种情况只能靠人挑一句干净的。
